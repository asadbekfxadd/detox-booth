# Vitamin B — сайт, касса и управление сетью соковых баров

Полный цикл одной системой: сайт для заказа, касса (POS), экран кухни, склад с рецептурами и партиями (FEFO), закупки, списания, клиенты и лояльность, финансы и аналитика, журнал действий.

**Стек:** Next.js 16 (App Router), TypeScript, Prisma 6 + PostgreSQL, Auth.js v5, Tailwind v4, Zod 4, Zustand, Recharts. Деньги — UZS, время — Ташкент (UTC+5).

## Быстрый старт

```bash
npm ci
cp .env.example .env        # заполните DATABASE_URL, AUTH_SECRET и SEED_*_PASSWORD
npx prisma migrate deploy   # создаёт таблицы
npx prisma db seed          # демо-данные (только для пустой тестовой базы!)
npm run dev                 # http://localhost:3000
```

Войти в админку: `/login`, логины демо-сотрудников выводит сидер (`owner@`, `admin@`, `cashier@`, `warehouse@`, `barista@detoxbooth.uz`), пароли — из `SEED_*_PASSWORD`.

Меню из 41 позиции (с фото, опциями размера, молока, добавок, льда и сладости) загружается отдельно и безопасно запускается повторно:

```bash
npx tsx prisma/seed-menu.ts
```

## Деплой (Railway)

Сборка: `npx prisma generate && npm run build`. Запуск: `npx prisma migrate deploy && npx next start -H 0.0.0.0 -p $PORT` — миграции применяются автоматически перед стартом.

Обязательные переменные: `DATABASE_URL`, `AUTH_SECRET`, `AUTH_TRUST_HOST=true`, `NEXTAUTH_URL`. Остальное — в `.env.example`.

**Мандаринка (помощница на сайте).** Работает сразу: подбирает напитки по меню на русском и узбекском. Чтобы включить свободный чат на Claude, задайте `ANTHROPIC_API_KEY` (на сервере); `MANDARIN_DAILY_LIMIT` ограничивает число сообщений к ИИ в сутки (по умолчанию 600), дальше она сама переключается на подбор без ИИ.

## Новое заведение (ресторан, кафе)

Каждое заведение получает свою копию сайта и свою базу. Название, логотип, цвета и тексты меняются в админке («Бренд и сайт»), код трогать не нужно.

1. Создайте на Railway проект из этого репозитория и добавьте PostgreSQL.
2. Задайте переменные: `DATABASE_URL`, `AUTH_SECRET`, `AUTH_TRUST_HOST=true`, `SITE_URL` (адрес сайта) и `BRAND_PRESET=blank` (нейтральный бренд вместо Vitamin B).
3. После первого деплоя один раз выполните первичное заполнение: `BLANK_OWNER_EMAIL=… BLANK_OWNER_PASSWORD=… BLANK_BRAND_NAME="Название" npm run seed:blank`. Скрипт ничего не стирает: он создаёт владельца (пароль не короче 12 знаков), одну точку и бренд, и откажется работать в базе, где уже есть сотрудники.
4. Войдите в админку, откройте «Бренд и сайт», «Настройки», добавьте категории, продукты, столы. Подключите свой домен в настройках Railway.

## Зал и официанты

Роль «Официант» (Админка → Сотрудники) попадает на `/waiter`: сетка столов, заказ с телефона, подачи («Сразу», «Горячее», «Десерт»). Горячее и десерт можно придержать: на кухню такой заказ уходит кнопкой «На кухню». Официант может попросить счёт, отметить заказ поданным, пересадить гостей на другой стол (занятый стол — счета объединяются). Оплату принимает кассир на `/pos/tables/…`. Роли «Менеджер» и «Кассир» тоже видят зал.

### Сервисный сбор, чаевые, раздельная оплата

- Админка → Настройки → «Сервисный сбор за столом, %». Сбор добавляется к заказам при оплате и входит в выручку; гость видит его в счёте. 0 — выключен.
- На кассе (`/pos/tables/…`) кассир отмечает, какие заказы платит гость, добавляет чаевые (кнопки 5/10/15% или своя сумма) и принимает оплату. Счёт стола закрывается, когда оплачен последний заказ.
- Чаевые не входят в выручку. В отчёте смены они отдельной строкой; наличные чаевые входят в «ожидается в кассе», пока их не выдали официанту.

## Кухня и печать

- **Станции** (Админка → Категории → «Станции кухни»): бар, горячий цех, холодный цех. К станции привязываются категории меню. На экране кухни появляются вкладки: каждая станция видит только свои позиции и отмечает их кнопкой «Готово · станция». Заказ становится «Готов», когда готовы все станции. Без станций кухня работает как раньше.
- **Печать** (лента 80 мм, через диалог печати браузера): бегунок для кухни (`/print/kitchen/…`, можно по станции), предварительный счёт и чек стола (`/print/bill/…`), чек заказа (`/print/order/…`). Кнопки есть на кухне, в кассе, у официанта и в карточке заказа. Чеки не фискальные: подключение soliq делается отдельно.
- **Автопечать на кухне:** кнопка «Включить автопечать» печатает бегунок на каждый новый заказ, пока экран кухни открыт. Чтобы не было диалога печати, запустите Chrome кухонного компьютера с флагом `--kiosk-printing` и выберите принтер по умолчанию. Тихая печать на сетевой принтер без браузера (ESC/POS) — отдельная доработка.

## Доставка и курьеры

- **Зоны доставки** — Админка → Доставка → «Зоны доставки»: название, стоимость, минимальный заказ и «бесплатно от». Если зоны есть, клиент на сайте выбирает зону, цена и минимум считаются на сервере. Если зон нет, работает единая стоимость из «Настроек».
- **Курьеры** — сотрудники с ролью «Курьер», привязанные к точке. После входа курьер попадает на `/courier`: свободные заказы можно взять (кто первый, тот и взял), затем «Забрал, выезжаю» и «Доставил». Наличные при доставке фиксируются как оплата.
- **Диспетчер** — Админка → Доставка: доска «Готовится / Готовы, нужен курьер / В пути / Доставлены». Курьера можно назначить или снять до выезда, заказ можно отметить доставленным вручную.
- Если у точки есть курьеры, кухня не выдаёт доставку сама: на карточке написано, что ждём курьера. Без курьеров всё работает как раньше.
- Клиент на странице заказа видит имя курьера и статус «везёт». Уведомлений курьерам (Telegram/SMS) и живого GPS пока нет.

## Оплата, бронь, счастливые часы

- **Payme и Click** — онлайн-оплата заказов с сайта. Включается переменными Railway: `PAYMENT_PROVIDERS=payme,click`, для Payme `PAYME_MERCHANT_ID`, `PAYME_KEY` (`PAYME_TEST=1` для тестовой кассы), для Click `CLICK_SERVICE_ID`, `CLICK_MERCHANT_ID`, `CLICK_SECRET_KEY`. В кабинетах сервисов укажите адреса: Payme — `https://ВАШ-САЙТ/api/payments/payme`, Click — `https://ВАШ-САЙТ/api/payments/click` (prepare и complete). Клиент выбирает сервис на оформлении, оплачивает на странице сервиса и возвращается на страницу заказа; если не оплатил, на странице заказа остаётся кнопка «Оплатить онлайн». Возврат из Payme работает, пока заказ ещё «Новый» (иначе Payme получает отказ, возврат делается через кабинет Payme). Не подключайте сервис, пока не проверите оплату в тестовом режиме.
- **Бронь столов** — Админка → Настройки (включить), у столов указываются места. Гость бронирует на сайте («Бронь стола»), стол подбирается автоматически, двойная бронь исключена, у брони есть страница с отменой. Админка → Брони: подтверждение, пересадка, «пришли», «не пришли», отметка депозита. Депозит принимает персонал (онлайн-оплата депозита не подключена). Официант видит сегодняшние брони на главной.
- **Счастливые часы** — Админка → Счастливые часы: скидка в % по дням недели и времени (Ташкент) на всё меню или одну категорию. Цена считается на сервере для сайта, кассы, официанта и стола; на сайте видна старая цена.
- Чеки пока не фискальные: подключение soliq (фискализация) делается отдельно и требует данных вашей кассы.

## Акции

- **Акции без промокода** — Админка → Акции. Применяются к корзине сами, на сайте и на кассе. Четыре вида: «Купи N — получи» (2+1, второй за полцены, на категорию или продукт), «Набор по цене» (боул и фреш вместе за фиксированную сумму), «Скидка от суммы» (ступени: от 100 000 — 5%, от 200 000 — 10%), «Первый заказ» (клиента узнаём по телефону). Для каждой можно задать дни недели, часы, даты, общий лимит и лимит на клиента, а также где она действует (сайт, касса).
- **Как считается:** сначала акции на позиции (каждая штука участвует только в одной), затем одна самая выгодная скидка на сумму, затем промокод или ручная скидка. По умолчанию промокод вместе с акцией нельзя (можно разрешить галочкой в акции). Позиции со счастливыми часами в акциях на позиции не участвуют, если не включить это в акции.
- **Что видит гость:** страница «Акции» (ссылка появляется в шапке, когда есть хотя бы одна акция или счастливые часы), строки акций в корзине и при оформлении и подсказки вроде «добавьте ещё 1 шт. — одна бесплатно».
- Акции не применяются к заказам за столом и у официанта (там скидок нет). Применённые акции записываются в заказ, в списке видно, сколько раз акция сработала и сколько скидок выдано. Использованную акцию удалить нельзя, её отключают.

## Безопасность и эксплуатация

- Цены, скидки, баллы и наличие всегда считает сервер; браузер присылает только id, опции и количество.
- Склад: любая операция с остатками берёт блокировку точки, поэтому два одновременных заказа не уведут партию в минус.
- Вход ограничен по частоте (30 попыток с адреса и 8 на логин за 15 минут), заказы с сайта — 8 за 10 минут с адреса. Счётчики хранятся в памяти процесса: при нескольких экземплярах сервера их нужно вынести в Redis.
- Заголовки безопасности заданы в `next.config.ts`.
- Сидер `prisma/seed.ts` стирает все данные и откажется работать в непустой базе без `ALLOW_DESTRUCTIVE_SEED=yes`.
- Онлайн-оплата: Payme и Click подключены (см. раздел «Оплата, бронь, счастливые часы»); по умолчанию включена только оплата при получении.

Подробнее об устройстве: `docs/ARCHITECTURE.md`. Результаты аудита: `docs/AUDIT.md`.

## Мандаринка в корзине и напоминания

- **Совет в корзине.** Мандаринка предлагает, что добавить, по порядку важности: чего не хватает акции («Почти! Добавьте ещё 1 шт. — одна бесплатно», кнопка добавляет ровно то, что нужно) → сколько осталось до следующей ступени скидки (полоса прогресса и позиции, которые закрывают разрыв) → «к вашему боулу гости часто берут» → в корзине одни напитки или одна еда → хиты. Фраза «часто берут» показывается только если пара встретилась минимум в 3 настоящих заказах за 90 дней (без отменённых); иначе её нет. Если акция только что сработала, Мандаринка радуется и называет сумму экономии.
- **Оформление.** При доставке показывается полоса «добавьте ещё X — доставка бесплатно» по порогу выбранной зоны и позиции, которые добавляются одним касанием.
- **Напоминания** (только если Мандаринка включена в настройках): 75 секунд без действий, курсор ушёл за верхний край окна (только на компьютере), возвращение через 20+ минут с непустой корзиной; пока вкладка скрыта, в заголовке «🍊 Ваш заказ ждёт». Не больше 3 раз за визит, не чаще раза в 4 минуты, «Позже» отключает на 30 минут, на страницах корзины, оформления и заказа молчит. Счётчики хранятся в браузере гостя, на сервер ничего не уходит.

## Видео «Как готовим»

- В карточке товара в админке (Продукты → товар) есть поле «Видео». Вставьте ссылку на YouTube (в том числе Shorts), прямую ссылку на файл `.mp4`/`.webm` или любую другую страницу с видео, например рилс в Instagram.
- На странице позиции поверх фото появляется кнопка «Как готовим», на карточке в меню — значок «Видео». YouTube и файлы открываются в окне поверх страницы (Esc или клик по фону закрывает), остальные ссылки открываются в новой вкладке.
- Видео не грузится, пока гость не нажал кнопку, поэтому скорость страницы не страдает. Ссылка должна начинаться с `https://`. Лучше всего короткий вертикальный ролик до 30 секунд. Сами файлы сайт не хранит: загрузите ролик на YouTube или в любое хранилище и вставьте ссылку.

### Анимация сборки и описание для AI-видео

- **«Смотреть сборку».** Для напитков (фреши, смузи, детокс, шоты, лимонады, кофе и чай), у которых нет своего видео, на странице позиции появляется кнопка с анимацией: по одному ингредиенту (до трёх) кладут на доску, рубят ножом и «бац» в блендер, смесь взбивается, банку поднимают над стаканом, наклоняют и льют, в стакан ставят трубочку. Длина цикла зависит от числа ингредиентов (11 секунд для одного, 17 для трёх), расписание считает `lib/prep-timeline.ts`.
- **Цвет напитка** берётся из ингредиентов: апельсин даёт оранжевый, клубника красный, шпинат зелёный, главным считается первый яркий ингредиент, остальные подмешиваются на 30%, молоко только высветляет. Нет данных: цвет категории. Цвета ингредиентов лежат в таблице `lib/ingredients.ts`.
- Ингредиенты берутся из рецепта (упаковка не считается). Лёд, молоко, мёд и злаки не режут, их на доске нет. Если рецепта нет, ищем ингредиенты в названии и описании; если нет ничего подходящего, в блендер без ножа падает эмодзи категории. Без видеофайлов и библиотек: SVG и CSS. При включённом «уменьшении движения» показывается готовый стакан. Анимация честно подписана «Иллюстрация»: это не съёмка вашей кухни.
- **Если у позиции есть настоящее видео**, показывается оно и кнопка «Как готовим», анимация не нужна. Боулы и салаты без видео остаются без кнопки: собирать их из эмодзи бессмысленно.
- **Описание для AI-видео.** В админке (Продукты → товар → «Описание для AI-видео») автоматически собирается готовое описание на английском из названия, объёма и ингредиентов: вертикальное 9:16, 8 секунд, без текста, логотипов и людей. Нажмите «Скопировать», вставьте в любой AI-генератор видео (Veo, Sora, Kling, Runway, Luma), скачайте ролик, загрузите на YouTube или в хранилище и вставьте ссылку в поле «Видео». Текст можно править перед копированием.
- Чтобы анимация показывала настоящие ингредиенты, заведите рецепт у позиции (Склад → Рецепты).

## Склад одним разделом

В меню один пункт «Склад» (`/admin/inventory`): все продукты с остатками, минимумом, ближайшим сроком и ценой в одной таблице с поиском и фильтрами «Мало» и «Срок горит». Отсюда: «+ Приход» (списком, из строки продукта сразу с этим продуктом), «+ Новый продукт», «Заказать у поставщика», перемещение и инвентаризация. Закупки, поставщики, списания, партии и расхождения открываются вкладками над страницей. Старые адреса (`/admin/ingredients`, `/admin/purchases` и другие) работают, список ингредиентов ведёт на «Склад».

## «Скоро будет доступно» и остатки на сайте

Продукт без рецепта на сайте показывается как **«Скоро будет доступно»**: кнопки нет, в корзину и заказ он не попадает (сервер проверяет и в обход кнопки, `assertSellableOnSite`). Как только в «Рецептах» у продукта вписаны ингредиенты и граммы на порцию, он продаётся, и дальше его наличие считается по остатку склада точки: нет остатка, значит «Скоро вернём»; мало (до 5 порций), значит «Осталось всего N шт.». Так сайт всегда равен складу, а недоделанные продукты закрыты сами.

Настройка «Продавать на сайте только продукты с рецептом» (Настройки → Заказы) включена по умолчанию; выключите, чтобы продавать и продукты без рецепта. Касса и официант этим не ограничены. На странице «Рецепты» показано, у скольки продуктов рецепт готов.

### Создать продукт по описанию

Продукты → «+ Создать по описанию». Пишете обычным текстом, например: «Яблочный фреш: яблоко 300 г, морковь 150 г, лимон 20 г. Размеры 300 и 500 мл, цена 25000 и 38000» (можно и построчно, и «0,2 кг», «банан 1 шт», «0,5 л», «25к»). Система разбирает название, состав, размеры и цены, подбирает ингредиенты на складе (с учётом падежей: «яблока» = «Яблоко»), угадывает категорию и пишет описание карточки, потом показывает итог на проверку. Граммы указываются на первый (самый маленький) размер, на остальные пересчитываются пропорционально объёму. После кнопки создаются недостающие ингредиенты (без цены), продукт (сразу доступен в меню), размеры и рецепт; откроется редактор рецепта, где можно всё поправить и вписать цены ингредиентов. Разбор текста без ИИ, правилами (`lib/product-draft.ts`, тесты `tests/product-draft.test.ts`); ничего не угадывается молча: непонятные куски и приблизительные совпадения показываются предупреждениями. Фото добавляется в карточке продукта.

### Перевод ингредиента в другую единицу (шт → кг)

Склад → ингредиент → «Перевести в другую единицу». Выбираете новую единицу, для шт ↔ кг/л вписываете вес одной штуки (например, 150 г), для вес ↔ объём плотность (вода и соки = 1). Под полем виден результат («3 шт → 0,45 кг»). Пересчитываются остатки, партии, рецепты и граммовка по размерам, приходы, списания, движения, доп. ингредиенты опций и минимальный остаток; цена за единицу пересчитывается так, что суммы в деньгах не меняются. Запись в журнале «Единица ингредиента изменена». Стакан из «Своего микса» (в штуках) так переводить нельзя.

### Рецепт по размерам (300 мл / 500 мл)

Если у продукта есть обязательный выбор «Объём» (или «Размер», «Порция»), в «Рецептах» у каждого размера своя колонка: например, апельсин 300 г на 300 мл и 500 г на 500 мл. Именно эта граммовка списывается со склада при продаже размера, входит в себестоимость и маржу и учитывается в наличии на сайте. Каждый размер должен иметь хотя бы один ингредиент. Если ингредиент размеру не нужен, оставьте поле пустым. У продуктов без размеров рецепт один, как раньше. Хранится в таблице `RecipeSizeItem` (миграция `20261019000000_recipe_sizes`); для размеров без своих строк действует прежнее правило «основной рецепт × коэффициент».

Всё в рецепте вписывается руками и пересчитывается сразу: граммы/мл по каждому размеру, цена каждого ингредиента за 1 кг/л/шт (сохраняется в карточку ингредиента, в журнале «Ингредиент изменён», только у тех, кто видит себестоимость), название размера («330 мл») и его цена продажи (разница с ценой продукта пишется в надбавку размера). Следующий приход пересчитает среднюю цену по закупке, как обычно.

**Редактор рецепта «как конструктор»** (Рецепты → продукт): правится всё, ничего не закреплено. Название продукта; размеры: кнопки «+ 250 мл», «+ 330 мл», «+ 1 л» или свой («350 мл», «Большой»), лишний размер убирается крестиком, можно оставить один («только 500»); у каждого размера своя цена и граммовка. Новый размер копирует граммы и цену ближайшего по объёму и пересчитывает пропорционально (250 от 500 → половина), дальше правится руками. Самый дешёвый размер — по умолчанию, его цена = цена продукта; при одном размере выбор на сайте пропадает, а «Объём» в карточке подставляется из названия размера. Продукт без размеров можно разбить на размеры тем же кнопками. Размеры хранятся в модификаторе «Объём»; в заказах прошлых дат остаются как были (в позиции записан снимок названия и цены).

### Брутто и нетто (выход годного)

У ингредиента есть поле «Выход годного после обработки, %» (по умолчанию 100, потерь нет). Из 1000 г апельсина выходит 450 мл сока: пишите 45. В рецепте вы по-прежнему указываете то, что попадает в стакан (нетто, например 225 мл), а со склада списывается брутто: 225 ÷ 0,45 = 500 г апельсина. То же правило работает в наличии на сайте и на кассе (сколько порций можно приготовить), в проверке остатков при заказе, в себестоимости, калькуляции и аналитике. Менять выход можно в карточке ингредиента или прямо в таблице рецепта (колонка «Выход, %», под граммами видно «со склада: 500 г»); изменение пишется в журнал как «Ингредиент изменён», правка из рецепта требует доступа к складу. Хранится в `Ingredient.yieldPct` (миграция `20261025000000_ingredient_yield`); расчёт в `lib/yield.ts`, пересчёт потребности в `applyYield` (`services/availability.ts`). Прошлые заказы не пересчитываются: списания уже записаны.

### Заготовки и акт приготовления

Раздел «Склад → Заготовки» для полуфабрикатов, которые готовят заранее: сок-основа, сироп, пюре. У заготовки есть рецепт: из чего (сколько сырья берёте со склада) и сколько получается (например, 11 000 г апельсина → 5 000 мл сока; потери при обработке уже внутри этого выхода). Заготовка живёт на складе как обычный продукт (категория «Заготовки»): её можно класть в рецепты напитков, списывать, считать при инвентаризации.

**Акт приготовления**: выбираете заготовку, точку и сколько готовите (сырьё пересчитывается пропорционально, чего не хватает видно сразу). Система списывает сырьё по FEFO (только годное), считает реальную стоимость списанных партий и ставит заготовку на склад партией с этой себестоимостью; средняя цена заготовки пересчитывается. Если получилось меньше или больше, впишите фактическое: сырьё спишется по плану, а себестоимость единицы посчитается от факта. Акты хранятся в `ProductionAct` / `ProductionActItem`, в журнале движений это `PRODUCTION_OUT` и `PRODUCTION_IN` (миграция `20261025120000_prep_production`). Заготовка не может входить сама в себя, в том числе через другие заготовки. Рецепт может менять тот, у кого есть право на рецепты, акт оформляет тот, кто работает со складом.

### Оборотная ведомость

«Склад → Оборотная ведомость»: по каждому продукту остаток на начало периода, приход, из заготовок, продажи, списания, в заготовки, перемещено, поправки (инвентаризация) и остаток на конец, плюс сумма на конец. Остаток на любую дату: поставьте её в оба поля и смотрите «На конец». Даты по Ташкенту. Считается от текущего остатка назад по журналу движений, поэтому сходится с реальным складом, даже если часть остатков внесли без журнала. Возврат при отмене заказа уменьшает «Продажи». Кнопка «Скачать для Excel (CSV)» отдаёт то же в кг/л/шт с десятичной запятой.

### Автозаказ поставщикам

«Склад → Закупки → Автозаказ»: система сама собирает, что и у кого заказать. Продукт попадает в список, когда остаток плюс уже заказанное (черновики и оформленные закупки) ниже точки заказа, то есть большего из минимального остатка и расхода за срок доставки. Заказывается до уровня: большее из «максимума» продукта и расхода за N дней запаса. Расход считается по продажам и актам приготовления за последние 30 дней. Количество округляется вверх (по 100 г или мл, штуки целые), цена берётся из последней приёмки, а если её нет, из средней цены. Позиции группируются по поставщику; у продуктов без поставщика пометка, заказать их нельзя, пока поставщик не указан в карточке. Количество и галочку можно поменять у каждой строки, «Запас» и «Срок доставки» пересчитывают предложение.

Кнопка создаёт **черновики**, по одному на поставщика (ничего не оформляется). Откройте черновик, проверьте и нажмите «Оформить заказ»; в карточке закупки есть готовый текст для поставщика с кнопкой «Скопировать» (для Telegram или WhatsApp). Принимается закупка как обычно. Логика в `lib/auto-order.ts` и `services/auto-order.ts`, запись в журнале «Автозаказ: черновики закупок».

### Отчёты по сотрудникам и меню

«Аналитика → Продажи по сотрудникам»: по каждому кассиру и официанту число заказов, выручка, средний чек, скидки (сумма и процент от суммы до скидок, больше 15% подсвечивается), чаевые, отмены и возвраты. Продажа засчитывается тому, кто принял заказ; заказ официанта, закрытый на кассе, виден обоим (каждому со своей ролью), поэтому строки нельзя складывать. Заказы с сайта и киоска идут в строку «Без сотрудника». Логика в `lib/staff-report.ts`, запросы в `services/reports.ts`.

«Аналитика → ABC×XYZ и непродаваемые»: ABC по выручке за 12 недель плюс XYZ по стабильности недельных продаж (разброс до 10% — X, до 25% — Y, выше — Z) с подсказкой, что делать с блюдом. У блюд с менее чем 8 продажами стоит пометка «мало данных». Новые блюда, которые продаются меньше 12 недель, выглядят нестабильными: это ограничение метода. ### Внесение и изъятие наличных

В смене кассира «Касса → Смена» есть форма «Внести или изъять наличные»: размен, инкассация, оплата поставщику из кассы. Нужны сумма и причина. Движения входят в «Ожидается в кассе» (`+ внесено`, `− изъято`), видны в отчёте смены и записываются в журнал действий. Изъять больше, чем лежит в кассе по системе, нельзя. Таблица `CashMovement`.

### Отмена позиции в заказе стола

В заказах стола (на кассе и у официанта) у каждой позиции есть «Отменить позицию»: можно убрать часть порций или всю позицию, причина обязательна. Пока заказ не отправлен на кухню, отменяет любой сотрудник. После отправки нужно право отмены заказов (владелец, админ, менеджер) либо подтверждение менеджера: его email и пароль в той же форме (5 попыток за 10 минут). Итог заказа и ожидающий платёж пересчитываются; если убрали последнюю позицию, заказ отменяется. Оплаченный заказ так не отменить, для него есть возврат. Продукты, уже списанные со склада, не возвращаются: блюдо могли приготовить, это потери. Позиция удаляется из заказа, а след остаётся в таблице `VoidedItem` и виден в «Аналитика → Продажи по сотрудникам → Отменённые позиции» (кто отменил, кто подтвердил, «после кухни»).

Перенос стола и объединение счетов уже были («Пересадить гостей» у официанта).

## Telegram-бот и Mini App для покупателей

Покупатель открывает бота, нажимает «Меню» и видит тот же сайт Vitamin B внутри Telegram: меню, свой микс, акции, бронь стола, корзина и заказ. Отдельного приложения нет, это обычный сайт, который узнаёт, что открыт в Telegram (`components/site/TelegramApp.tsx`: разворачивает окно, красит шапку под бренд, включает кнопку «Назад»). В обычном браузере ничего не меняется и скрипт Telegram не грузится.

**Подключение (один раз):**
1. В Telegram откройте @BotFather → `/newbot` → название и имя бота. Получите токен.
2. В Railway, сервис сайта → Variables: `TELEGRAM_BOT_TOKEN` = токен (хранится только там, в код и в чат его не нужно). Сервис перезапустится.
3. В админке откройте «Telegram-бот» и нажмите «Подключить бота». Страница сама настроит вебхук, команды `/menu /orders /locations /help`, кнопку «Меню» (открывает сайт как Mini App) и описание бота. Нужен https-адрес сайта (`SITE_URL`).

**Что видит покупатель:** `/start` с приветствием и кнопками (меню, мои заказы, точки, «Поделиться номером»), `/orders` со ссылками на заказы, `/locations`. Если поделиться номером, он подтверждён самим Telegram и подставится в заказ. В форме заказа сразу стоят имя и номер. «Мои заказы» хранятся на сервере и видны на любом устройстве. Бот пишет в чат: заказ принят, подтверждён, готов (для доставки: курьер в пути), выдан (с баллами), отменён. Статус «готовится» молчит, чтобы не шуметь.

**Безопасность:** вход в Mini App без паролей. Сервер проверяет подпись `initData` (HMAC-SHA256 по токену бота, как в документации Telegram, данные живут не дольше суток) при каждом заказе и запросе истории, куки для этого не используются. Заказ с неверной подписью оформляется как обычный без привязки к Telegram. Вебхук принимает только запросы с секретным заголовком (секрет считается из `AUTH_SECRET` и токена). Бот отвечает только в личных чатах; чужой контакт вместо своего номера не принимается; если пользователь заблокировал бота, ему больше не пишем. Сайт разрешено встраивать только в Telegram (`frame-ancestors` с адресами telegram.org); кабинет, касса и остальные служебные разделы встраивать по-прежнему нельзя.

**Данные:** таблица `TelegramUser` (id, имя, username, подтверждённый телефон, признак блокировки) и поле `Order.telegramId` (миграция `20261026120000_telegram`). Логика: `lib/telegram.ts` (проверка подписи, вызовы Bot API), `lib/telegram-messages.ts` (тексты), `services/telegram.ts` (бот, уведомления, подключение), `app/api/telegram/webhook`. Ограничение: в веб-версии Telegram (в браузере) сайт открывается во фрейме, и браузеры с блокировкой сторонних куки могут не запомнить выбранную точку; в приложениях Telegram на телефоне и компьютере всё работает как на сайте.

**Номер и геопозиция при входе.** Когда человек впервые открывает Mini App, внизу появляется необязательное окно «Давайте познакомимся» (`components/site/TelegramWelcome.tsx`): «Поделиться номером» (родной запрос Telegram, номер приходит боту и подтверждён самим Telegram) и «Определить, где я» (запрос места через Telegram, а в старых клиентах через браузер; только по нажатию кнопки). По месту находится ближайшая активная точка и выбирается на сайте, расстояние считается по прямой (`lib/geo.ts`). «Не сейчас» прячет окно на 3 дня; когда номер и место уже есть, оно не показывается. То же есть в чате с ботом: кнопки «Поделиться номером» и «Где я» (отправка места), бот отвечает ближайшей точкой.

Что хранится: координаты округляются до ~100 м и лежат в `TelegramUser.lat/lng/locatedAt`. В заказ на доставку они попадают только если покупатель оставил галочку «Показать курьеру, где я», и берутся с сервера (сохранённые у проверенного пользователя Telegram, а не присланные браузером) в `Order.deliveryLat/deliveryLng`. Сотрудники видят ссылку на карту в карточке заказа, на доске доставки и в кабинете курьера; в карточке заказа также виден @username клиента. Адрес текстом по-прежнему обязателен. Миграция `20261026180000_telegram_geo`.

Важно: чтобы ближайшая точка находилась, у точек должны быть координаты (Настройки → «Адрес и телефон точек», поле координат, например `41.311081, 69.240562`). Если координат нет, место сохраняется, а точку человек выбирает сам. Точки дальше 40 км от клиента не предлагаются.

## Новая точка (филиал)

Настройки → «Добавить точку (новый филиал)» (`/admin/settings`, право `settings.edit`): название, адрес, координаты, телефон и, по желанию, сразу учётка менеджера (имя, email, пароль, роль «Менеджер», привязана к точке; поля менеджера заполняются все три или ни одного). Точка появляется на сайте, в выборе точки и в кассе; склад у неё начинается с нуля и заработает после первого прихода («Склад → Приход»). Остальных сотрудников добавляйте в «Сотрудники», зоны доставки задаются в разделе «Доставка», столы в «Столы и QR». Название уникально без учёта регистра. Создание пишется в журнал («Добавлена точка»). Логика: `createLocation` в `services/locations.ts`, тесты `tests/locations.test.ts`.

## Календарь выручки

«Бизнес → Календарь выручки» (`/admin/calendar`, смотреть: `finance.view`, вносить и удалять: `finance.edit`, то есть владелец и бухгалтер). Месяц по дням: в каждой клетке выручка за день (завершённые заказы системы плюс внесённое вручную, оттенок зелёного показывает силу дня), пометка «вручную», если за день есть ручные записи. Стрелки листают месяцы, «Сегодня» открывает текущий день. Нажатие на день показывает итог, сумму по системе (заказы, средний чек, оплаты наличными, картой и онлайн), разбивку по точкам и список ручных записей.

Внести продажи можно за любой прошедший день (не раньше ~3 лет назад, в будущее нельзя): точка, сумма, способ оплаты и число чеков (необязательно), комментарий. Запись можно удалить; всё идёт в журнал действий. Выбор точки сверху ограничивает календарь одной точкой. День считается по Ташкенту (UTC+5). Важно: внесённое вручную показывается только в календаре и **не входит** в отчёты «Продажи» и «Финансы», чтобы не исказить прибыль и себестоимость; продажи, которые уже есть в системе, повторно вносить не нужно. Данные: таблица `DailySales` (миграция `20261031120000_daily_sales`), логика `services/revenue-calendar.ts` и `lib/revenue-calendar.ts`, тесты `tests/revenue-calendar.test.ts`.

## Видео «как готовим» в первом экране

«Бренд и сайт» → «Главная страница» → «Видео „как готовим“ в первом экране»: до 4 ссылок, по одной в строке, после « | » можно дописать подпись (`https://…/mango.mp4 | Свежий манго-смузи`). Вместо большой карточки в первом экране появляется видео, которое играет само, без звука, по кругу (`components/site/HeroVideo.tsx`). На телефоне оно стоит над заголовком, чтобы быть первым, что видит гость.

- **Что подходит:** прямой файл `.mp4` или `.webm` по https, свой файл на сайте (положите его в `public/videos/` в репозитории, ссылка `/videos/mango.mp4`) или ссылка YouTube (она открывается по нажатию, сама не грузится).
- **Какие ролики:** короткие (5–15 секунд), вертикальные или квадратные, до 5–8 МБ, формат H.264 (mp4); без звука играть начнут везде, включая телефоны.
- **Бережём трафик и нервы:** ролик играет, только пока карточку видно и вкладка открыта; при «уменьшении движения» в системе и в режиме экономии трафика автозапуска нет, гость нажимает «играть». Есть кнопки паузы и звука, точки для переключения роликов. Нерабочая ссылка пропускается.
- Если видео не заданы, первый экран выглядит как раньше. В универсальной главной (`classic`) видео тоже работает. Проверка ссылок: `safeVideoUrl` в `lib/brand-config.ts`, тесты `tests/brand-config.test.ts` и `tests/video.test.ts`. В карточке каждого продукта по-прежнему можно указать своё видео «Как готовим».

## Точка без учёта склада

У новой точки пустой склад, поэтому все позиции показываются как «Скоро вернём», пока не оформлен приход. Если склад на точке пока не ведётся, включите **«Продавать без учёта склада»**: Настройки → «Адрес и телефон точек» → галочка у точки (или сразу при добавлении новой точки), затем «Сохранить точки». Тогда все позиции с рецептом считаются в наличии на сайте, в кассе, у официанта и за столами, заказать можно без прихода товара.

Что при этом происходит: остатки и партии на этой точке не создаются и не списываются, уведомлений «мало на складе» нет, при отмене возвращать нечего. Себестоимость заказа считается по средней цене закупки ингредиентов, поэтому «Финансы» и «Калькуляция» остаются осмысленными. Когда будете готовы вести склад, снимите галочку, оформите приход («Склад → Приход») и сделайте инвентаризацию. Позиции без рецепта по-прежнему показываются как «Скоро будет доступно». Поле `Location.trackStock` (миграция `20261031140000_location_track_stock`), логика `usableStock` в `services/availability.ts` и `deductInventoryTx` в `lib/services/order-fulfillment.ts`.

## Сочные фото напиткам
Продукты → «Сочные фото напиткам» (`/admin/products/photos`, право `products.edit`). Для каждого напитка (категории смузи, фреши, соки, детокс, лимонады, коктейли, напитки) подбирается фото по названию из готовой библиотеки бесплатных снимков Unsplash (`lib/drink-photos.ts`: апельсин, морковь, свёкла, ягоды, манго-кокос и т. д.). Напиток без точного совпадения получает общее фото (смузи или соки). Видно текущее и новое фото, новое можно сменить в списке. Заранее отмечены напитки без фото и с точным подбором; остальные отмечаются вручную. «Применить» меняет `Product.image`, в журнале действий остаётся запись «Подобраны фото напиткам». Свои фото по-прежнему можно задать в карточке продукта.

## Простота для новичка

Админка рассчитана на человека без опыта: меньше терминов, больше подсказок.
- **«С чего начать»** на Обзоре (для владельца и администратора): 7 шагов (адрес и телефон, меню, приход на склад, рецепты, сотрудники, расходы, первая смена) с кнопкой «Открыть» у каждого. Галочки ставятся сами по данным, блок исчезает, когда всё сделано (`services/start-guide.ts`).
- **Понятные подписи**: «Прибыль с продаж» вместо «Валовая прибыль», «Что остаётся с выручки» вместо «Валовой маржи», «Мало на складе» вместо «Заканчивается»; под каждой цифрой на Обзоре строка «что это». То же в Финансах («Сколько заработали»).
- **Уведомления по-русски** с остатком в кг/л/шт: «Мало на складе: Манго — осталось 1,5 кг, минимум 2 кг» (`lib/notify.ts`). Старые английские уведомления переписываются при показе. Причины списаний тоже по-русски.
- **Настройки**: разделы сворачиваются с пояснением в одну строку, «1 — включена, 0 — выключена» заменено выбором «Включено / Выключено».
- В списке продуктов вместо прочерка в себестоимости ссылка «задать рецепт»; «-0 UZS» больше не показывается.

## Приход на склад списком

«Склад → + Приход» (`/admin/inventory/receive`) оформляет всю поставку за раз: таблица строк (ингредиент, количество, цена, срок годности) и одна кнопка. **Всё считается в кг, л и штуках, граммов и миллилитров в приходе нет**: у количества стоит подпись «кг» / «л» / «шт», цена всегда за 1 кг, 1 л или 1 шт (на склад это переводится само: хранение остаётся в г, мл, шт, поэтому рецепты и остатки не меняются). Цена подставляется с последней закупки (а если закупок не было, средняя), так что вводить нужно только количество и то, что изменилось. Под строкой появляются подсказки об опечатках (не блокируют оформление): слишком большое количество, цена в разы выше или ниже прошлой («лишний ноль?», «цена за грамм?»), цена 0, повтор продукта. Ингредиент ищется по набору названия, Enter переводит на следующую строку. Окно «Вставить списком» принимает накладную из Excel или мессенджера, по строке на позицию: `название; количество [единица]; цена; срок годности` (цена и срок необязательны; количество без единицы считается в кг, л или шт, цена за 1 кг/л/шт, например `Клубника; 5 кг; 60000`; «500 г» и «250 мл» тоже поймёт и переведёт в 0,5 кг и 0,25 л). Строки, которые не удалось разобрать, остаются в поле с понятной ошибкой.

Те же единицы в закупках и приёмке заказа поставщика, списаниях, перемещениях, инвентаризации, остатках склада и таблицах партий. Граммы остаются только там, где иначе неудобно: расход на порцию в рецептах и масса состава «Своего микса». Проверки на опечатки — `lib/receive-check.ts`.

**Нового продукта нет в списке?** В строке прихода под названием появится «+ Создать «…»»: выберите категорию и единицу, и продукт создастся, а приход продолжится без перехода на другую страницу (введённые строки не пропадают). В «Вставить списком» новые названия с понятной единицей («Манго; 3 кг») создаются одной кнопкой для всех. Минимум остатка, срок годности и поставщика можно задать позже в карточке продукта, цена берётся из самого прихода.

Приход атомарен: если в одной строке ошибка, на склад не попадает ничего. Каждая строка создаёт свою партию и пересчитывает среднюю цену; в журнале одна запись «Приход на склад списком». До 100 строк за раз. Разбор вставки — `lib/receive-list.ts`, сервис — `stockInMany` в `services/inventory.ts`.

## Калькуляция (полная себестоимость)

Раздел «Меню → Калькуляция» (`/admin/costing`) считает полную себестоимость каждой позиции: **ингредиенты + упаковка + потери + амортизация оборудования + зарплата + аренда и коммунальные**, и показывает прибыль и маржу. Смотреть могут те, у кого есть `finance.view` (владелец, администратор, бухгалтер), менять оборудование — `finance.edit` (владелец, бухгалтер).

- **Ингредиенты**: количество в рецепте × средняя закупочная цена. Без рецепта себестоимость не показывается (она была бы неполной).
- **Упаковка** (стаканчик, крышка, трубочка): ингредиенты рецепта из категории «Packaging» или «Упаковка» плюс общая сумма на напиток из Настроек.
- **Потери**: процент от стоимости ингредиентов (Настройки → Калькуляция).
- **Амортизация**: «Оборудование» на странице калькуляции. Цена ÷ ресурс в напитках; оборудование можно привязать к категории (выжималка только к сокам). Выключенное оборудование не считается.
- **Зарплата**: оклад в карточке сотрудника (Сотрудники → сотрудник → «Оклад в калькуляции»), плюс процент взносов из Настроек, делится на число напитков в месяц. Кого не нужно учитывать (владелец), оставьте без оклада.
- **Аренда и прочие расходы**: из раздела «Финансы» берутся все расходы, кроме зарплаты (аренда, коммунальные, маркетинг, доставка, прочее), среднее в месяц за 90 дней; или одной суммой в Настройках. Если окладов в карточках нет, зарплатой считается расход «Зарплата» из «Финансов». Таблица «Расходы в месяц» на странице показывает все статьи и их долю на один напиток.
- **Число напитков в месяц**, на которое делятся зарплата и аренда: плановое из Настроек, а если оно 0 — фактически проданное за 30 дней. Пока продаж мало, укажите план, иначе на первые напитки ляжет вся аренда.

Расчёт чистый и покрыт тестами (`lib/costing.ts`, `tests/costing.test.ts`). Реальная себестоимость заказов в «Финансах» по-прежнему считается по ингредиентам при выдаче (`Order.cogs`); калькуляция — плановая полная себестоимость для цен и решений.

## Свой микс

Гость на сайте (и кассир или официант по просьбе гостя) сам собирает стакан из любых ингредиентов склада.

- **Настройка:** Админка → Меню → «Свой микс». Размеры стакана (название, цена, масса состава в граммах, стаканчик со склада), доплата за ингредиент (дорогие — манго, авокадо) и вес одной штуки для ингредиентов в штуках. Пока размеры не сохранены, микс выключен.
- **Цена** = цена размера + доплаты за выбранные ингредиенты. Считает сервер; браузер присылает только размер и id ингредиентов.
- **Состав:** масса состава делится между выбранными ингредиентами поровну. Столько же списывается со склада (FEFO), плюс стаканчик; себестоимость заказа считается как у обычных напитков. Упаковку в микс класть нельзя, ингредиентам в штуках нужен вес штуки.
- **Где:** сайт `/mix` (ссылка в шапке и баннер в меню), касса (плитка «Свой микс»), экран официанта. Заказ за столом и «Повторить заказ» тоже работают.
- **Как хранится:** в заказе позиция «Свой микс» — системный скрытый товар (`svoy-mix`, категория «Свой микс»; привяжите категорию к станции в «Категориях»). Размер и граммовка ингредиентов записаны в позиции как снимок, поэтому изменение цен не меняет старые заказы. Отмена заказа возвращает ингредиенты на склад.

## Телефон

Админка и касса удобны на телефоне. В админке меню открывается кнопкой «Меню» (панель с группами разделов), шапка в одну строку, таблицы прокручиваются вбок внутри своего блока. На кассе каталог занимает весь экран, а заказ (клиент, скидка, оплата) открывается с нижней панели «Заказ · N шт · сумма»; на широком экране корзина по-прежнему справа.
