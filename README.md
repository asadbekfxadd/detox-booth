# Vitamin B — сайт, касса и управление сетью соковых баров

Полный цикл одной системой: сайт для заказа, касса (POS), экран кухни, склад с рецептурами и партиями (FEFO), закупки, списания, клиенты и лояльность, финансы и аналитика, журнал действий.

**Стек:** Next.js 16 (App Router), TypeScript, Prisma 6 + PostgreSQL, Auth.js v5, Tailwind v4, Zod 4, Zustand, Recharts. Деньги — UZS, время — Ташкент (UTC+5).

## Быстрый старт

```bash
npm ci
cp .env.example .env        # заполните DATABASE_URL, AUTH_SECRET и SEED_*_PASSWORD
npx prisma migrate deploy   # создаёт таблицы
npx prisma db seed          # демо-данные (только для пустой тестовой базы!)
npm run dev                 # http://localhost:3000
```

Войти в админку: `/login`, логины демо-сотрудников выводит сидер (`owner@`, `admin@`, `cashier@`, `warehouse@`, `barista@detoxbooth.uz`), пароли — из `SEED_*_PASSWORD`.

Меню из 41 позиции (с фото, опциями размера, молока, добавок, льда и сладости) загружается отдельно и безопасно запускается повторно:

```bash
npx tsx prisma/seed-menu.ts
```

## Деплой (Railway)

Сборка: `npx prisma generate && npm run build`. Запуск: `npx prisma migrate deploy && npx next start -H 0.0.0.0 -p $PORT` — миграции применяются автоматически перед стартом.

Обязательные переменные: `DATABASE_URL`, `AUTH_SECRET`, `AUTH_TRUST_HOST=true`, `NEXTAUTH_URL`. Остальное — в `.env.example`.

**Мандаринка (помощница на сайте).** Работает сразу: подбирает напитки по меню на русском и узбекском. Чтобы включить свободный чат на Claude, задайте `ANTHROPIC_API_KEY` (на сервере); `MANDARIN_DAILY_LIMIT` ограничивает число сообщений к ИИ в сутки (по умолчанию 600), дальше она сама переключается на подбор без ИИ.

## Новое заведение (ресторан, кафе)

Каждое заведение получает свою копию сайта и свою базу. Название, логотип, цвета и тексты меняются в админке («Бренд и сайт»), код трогать не нужно.

1. Создайте на Railway проект из этого репозитория и добавьте PostgreSQL.
2. Задайте переменные: `DATABASE_URL`, `AUTH_SECRET`, `AUTH_TRUST_HOST=true`, `SITE_URL` (адрес сайта) и `BRAND_PRESET=blank` (нейтральный бренд вместо Vitamin B).
3. После первого деплоя один раз выполните первичное заполнение: `BLANK_OWNER_EMAIL=… BLANK_OWNER_PASSWORD=… BLANK_BRAND_NAME="Название" npm run seed:blank`. Скрипт ничего не стирает: он создаёт владельца (пароль не короче 12 знаков), одну точку и бренд, и откажется работать в базе, где уже есть сотрудники.
4. Войдите в админку, откройте «Бренд и сайт», «Настройки», добавьте категории, продукты, столы. Подключите свой домен в настройках Railway.

## Зал и официанты

Роль «Официант» (Админка → Сотрудники) попадает на `/waiter`: сетка столов, заказ с телефона, подачи («Сразу», «Горячее», «Десерт»). Горячее и десерт можно придержать: на кухню такой заказ уходит кнопкой «На кухню». Официант может попросить счёт, отметить заказ поданным, пересадить гостей на другой стол (занятый стол — счета объединяются). Оплату принимает кассир на `/pos/tables/…`. Роли «Менеджер» и «Кассир» тоже видят зал.

### Сервисный сбор, чаевые, раздельная оплата

- Админка → Настройки → «Сервисный сбор за столом, %». Сбор добавляется к заказам при оплате и входит в выручку; гость видит его в счёте. 0 — выключен.
- На кассе (`/pos/tables/…`) кассир отмечает, какие заказы платит гость, добавляет чаевые (кнопки 5/10/15% или своя сумма) и принимает оплату. Счёт стола закрывается, когда оплачен последний заказ.
- Чаевые не входят в выручку. В отчёте смены они отдельной строкой; наличные чаевые входят в «ожидается в кассе», пока их не выдали официанту.

## Кухня и печать

- **Станции** (Админка → Категории → «Станции кухни»): бар, горячий цех, холодный цех. К станции привязываются категории меню. На экране кухни появляются вкладки: каждая станция видит только свои позиции и отмечает их кнопкой «Готово · станция». Заказ становится «Готов», когда готовы все станции. Без станций кухня работает как раньше.
- **Печать** (лента 80 мм, через диалог печати браузера): бегунок для кухни (`/print/kitchen/…`, можно по станции), предварительный счёт и чек стола (`/print/bill/…`), чек заказа (`/print/order/…`). Кнопки есть на кухне, в кассе, у официанта и в карточке заказа. Чеки не фискальные: подключение soliq делается отдельно.
- **Автопечать на кухне:** кнопка «Включить автопечать» печатает бегунок на каждый новый заказ, пока экран кухни открыт. Чтобы не было диалога печати, запустите Chrome кухонного компьютера с флагом `--kiosk-printing` и выберите принтер по умолчанию. Тихая печать на сетевой принтер без браузера (ESC/POS) — отдельная доработка.

## Доставка и курьеры

- **Зоны доставки** — Админка → Доставка → «Зоны доставки»: название, стоимость, минимальный заказ и «бесплатно от». Если зоны есть, клиент на сайте выбирает зону, цена и минимум считаются на сервере. Если зон нет, работает единая стоимость из «Настроек».
- **Курьеры** — сотрудники с ролью «Курьер», привязанные к точке. После входа курьер попадает на `/courier`: свободные заказы можно взять (кто первый, тот и взял), затем «Забрал, выезжаю» и «Доставил». Наличные при доставке фиксируются как оплата.
- **Диспетчер** — Админка → Доставка: доска «Готовится / Готовы, нужен курьер / В пути / Доставлены». Курьера можно назначить или снять до выезда, заказ можно отметить доставленным вручную.
- Если у точки есть курьеры, кухня не выдаёт доставку сама: на карточке написано, что ждём курьера. Без курьеров всё работает как раньше.
- Клиент на странице заказа видит имя курьера и статус «везёт». Уведомлений курьерам (Telegram/SMS) и живого GPS пока нет.

## Оплата, бронь, счастливые часы

- **Payme и Click** — онлайн-оплата заказов с сайта. Включается переменными Railway: `PAYMENT_PROVIDERS=payme,click`, для Payme `PAYME_MERCHANT_ID`, `PAYME_KEY` (`PAYME_TEST=1` для тестовой кассы), для Click `CLICK_SERVICE_ID`, `CLICK_MERCHANT_ID`, `CLICK_SECRET_KEY`. В кабинетах сервисов укажите адреса: Payme — `https://ВАШ-САЙТ/api/payments/payme`, Click — `https://ВАШ-САЙТ/api/payments/click` (prepare и complete). Клиент выбирает сервис на оформлении, оплачивает на странице сервиса и возвращается на страницу заказа; если не оплатил, на странице заказа остаётся кнопка «Оплатить онлайн». Возврат из Payme работает, пока заказ ещё «Новый» (иначе Payme получает отказ, возврат делается через кабинет Payme). Не подключайте сервис, пока не проверите оплату в тестовом режиме.
- **Бронь столов** — Админка → Настройки (включить), у столов указываются места. Гость бронирует на сайте («Бронь стола»), стол подбирается автоматически, двойная бронь исключена, у брони есть страница с отменой. Админка → Брони: подтверждение, пересадка, «пришли», «не пришли», отметка депозита. Депозит принимает персонал (онлайн-оплата депозита не подключена). Официант видит сегодняшние брони на главной.
- **Счастливые часы** — Админка → Счастливые часы: скидка в % по дням недели и времени (Ташкент) на всё меню или одну категорию. Цена считается на сервере для сайта, кассы, официанта и стола; на сайте видна старая цена.
- Чеки пока не фискальные: подключение soliq (фискализация) делается отдельно и требует данных вашей кассы.

## Акции

- **Акции без промокода** — Админка → Акции. Применяются к корзине сами, на сайте и на кассе. Четыре вида: «Купи N — получи» (2+1, второй за полцены, на категорию или продукт), «Набор по цене» (боул и фреш вместе за фиксированную сумму), «Скидка от суммы» (ступени: от 100 000 — 5%, от 200 000 — 10%), «Первый заказ» (клиента узнаём по телефону). Для каждой можно задать дни недели, часы, даты, общий лимит и лимит на клиента, а также где она действует (сайт, касса).
- **Как считается:** сначала акции на позиции (каждая штука участвует только в одной), затем одна самая выгодная скидка на сумму, затем промокод или ручная скидка. По умолчанию промокод вместе с акцией нельзя (можно разрешить галочкой в акции). Позиции со счастливыми часами в акциях на позиции не участвуют, если не включить это в акции.
- **Что видит гость:** страница «Акции» (ссылка появляется в шапке, когда есть хотя бы одна акция или счастливые часы), строки акций в корзине и при оформлении и подсказки вроде «добавьте ещё 1 шт. — одна бесплатно».
- Акции не применяются к заказам за столом и у официанта (там скидок нет). Применённые акции записываются в заказ, в списке видно, сколько раз акция сработала и сколько скидок выдано. Использованную акцию удалить нельзя, её отключают.

## Безопасность и эксплуатация

- Цены, скидки, баллы и наличие всегда считает сервер; браузер присылает только id, опции и количество.
- Склад: любая операция с остатками берёт блокировку точки, поэтому два одновременных заказа не уведут партию в минус.
- Вход ограничен по частоте (30 попыток с адреса и 8 на логин за 15 минут), заказы с сайта — 8 за 10 минут с адреса. Счётчики хранятся в памяти процесса: при нескольких экземплярах сервера их нужно вынести в Redis.
- Заголовки безопасности заданы в `next.config.ts`.
- Сидер `prisma/seed.ts` стирает все данные и откажется работать в непустой базе без `ALLOW_DESTRUCTIVE_SEED=yes`.
- Онлайн-оплата: Payme и Click подключены (см. раздел «Оплата, бронь, счастливые часы»); по умолчанию включена только оплата при получении.

Подробнее об устройстве: `docs/ARCHITECTURE.md`. Результаты аудита: `docs/AUDIT.md`.

## Мандаринка в корзине и напоминания

- **Совет в корзине.** Мандаринка предлагает, что добавить, по порядку важности: чего не хватает акции («Почти! Добавьте ещё 1 шт. — одна бесплатно», кнопка добавляет ровно то, что нужно) → сколько осталось до следующей ступени скидки (полоса прогресса и позиции, которые закрывают разрыв) → «к вашему боулу гости часто берут» → в корзине одни напитки или одна еда → хиты. Фраза «часто берут» показывается только если пара встретилась минимум в 3 настоящих заказах за 90 дней (без отменённых); иначе её нет. Если акция только что сработала, Мандаринка радуется и называет сумму экономии.
- **Оформление.** При доставке показывается полоса «добавьте ещё X — доставка бесплатно» по порогу выбранной зоны и позиции, которые добавляются одним касанием.
- **Напоминания** (только если Мандаринка включена в настройках): 75 секунд без действий, курсор ушёл за верхний край окна (только на компьютере), возвращение через 20+ минут с непустой корзиной; пока вкладка скрыта, в заголовке «🍊 Ваш заказ ждёт». Не больше 3 раз за визит, не чаще раза в 4 минуты, «Позже» отключает на 30 минут, на страницах корзины, оформления и заказа молчит. Счётчики хранятся в браузере гостя, на сервер ничего не уходит.

## Видео «Как готовим»

- В карточке товара в админке (Продукты → товар) есть поле «Видео». Вставьте ссылку на YouTube (в том числе Shorts), прямую ссылку на файл `.mp4`/`.webm` или любую другую страницу с видео, например рилс в Instagram.
- На странице позиции поверх фото появляется кнопка «Как готовим», на карточке в меню — значок «Видео». YouTube и файлы открываются в окне поверх страницы (Esc или клик по фону закрывает), остальные ссылки открываются в новой вкладке.
- Видео не грузится, пока гость не нажал кнопку, поэтому скорость страницы не страдает. Ссылка должна начинаться с `https://`. Лучше всего короткий вертикальный ролик до 30 секунд. Сами файлы сайт не хранит: загрузите ролик на YouTube или в любое хранилище и вставьте ссылку.

### Анимация сборки и описание для AI-видео

- **«Смотреть сборку».** Для напитков (фреши, смузи, детокс, шоты, лимонады, кофе и чай), у которых нет своего видео, на странице позиции появляется кнопка с анимацией: по одному ингредиенту (до трёх) кладут на доску, рубят ножом и «бац» в блендер, смесь взбивается, банку поднимают над стаканом, наклоняют и льют, в стакан ставят трубочку. Длина цикла зависит от числа ингредиентов (11 секунд для одного, 17 для трёх), расписание считает `lib/prep-timeline.ts`.
- **Цвет напитка** берётся из ингредиентов: апельсин даёт оранжевый, клубника красный, шпинат зелёный, главным считается первый яркий ингредиент, остальные подмешиваются на 30%, молоко только высветляет. Нет данных: цвет категории. Цвета ингредиентов лежат в таблице `lib/ingredients.ts`.
- Ингредиенты берутся из рецепта (упаковка не считается). Лёд, молоко, мёд и злаки не режут, их на доске нет. Если рецепта нет, ищем ингредиенты в названии и описании; если нет ничего подходящего, в блендер без ножа падает эмодзи категории. Без видеофайлов и библиотек: SVG и CSS. При включённом «уменьшении движения» показывается готовый стакан. Анимация честно подписана «Иллюстрация»: это не съёмка вашей кухни.
- **Если у позиции есть настоящее видео**, показывается оно и кнопка «Как готовим», анимация не нужна. Боулы и салаты без видео остаются без кнопки: собирать их из эмодзи бессмысленно.
- **Описание для AI-видео.** В админке (Продукты → товар → «Описание для AI-видео») автоматически собирается готовое описание на английском из названия, объёма и ингредиентов: вертикальное 9:16, 8 секунд, без текста, логотипов и людей. Нажмите «Скопировать», вставьте в любой AI-генератор видео (Veo, Sora, Kling, Runway, Luma), скачайте ролик, загрузите на YouTube или в хранилище и вставьте ссылку в поле «Видео». Текст можно править перед копированием.
- Чтобы анимация показывала настоящие ингредиенты, заведите рецепт у позиции (Склад → Рецепты).

## Склад одним разделом

В меню один пункт «Склад» (`/admin/inventory`): все продукты с остатками, минимумом, ближайшим сроком и ценой в одной таблице с поиском и фильтрами «Мало» и «Срок горит». Отсюда: «+ Приход» (списком, из строки продукта сразу с этим продуктом), «+ Новый продукт», «Заказать у поставщика», перемещение и инвентаризация. Закупки, поставщики, списания, партии и расхождения открываются вкладками над страницей. Старые адреса (`/admin/ingredients`, `/admin/purchases` и другие) работают, список ингредиентов ведёт на «Склад».

## Приход на склад списком

«Склад → + Приход» (`/admin/inventory/receive`) оформляет всю поставку за раз: таблица строк (ингредиент, количество, цена, срок годности) и одна кнопка. Для скорости: ингредиент ищется по набору названия, Enter переводит на следующую строку, цена подставляется прежняя (средняя), для г и мл есть переключатель кг и л. Окно «Вставить списком» принимает накладную из Excel или мессенджера, по строке на позицию: `название; количество [единица]; цена; срок годности` (цена и срок необязательны, цена указывается за ту же единицу, что и количество, например `Клубника; 5 кг; 60000`). Строки, которые не удалось разобрать, остаются в поле с понятной ошибкой.

**Нового продукта нет в списке?** В строке прихода под названием появится «+ Создать «…»»: выберите категорию и единицу, и продукт создастся, а приход продолжится без перехода на другую страницу (введённые строки не пропадают). В «Вставить списком» новые названия с понятной единицей («Манго; 3 кг») создаются одной кнопкой для всех. Минимум остатка, срок годности и поставщика можно задать позже в карточке продукта, цена берётся из самого прихода.

Приход атомарен: если в одной строке ошибка, на склад не попадает ничего. Каждая строка создаёт свою партию и пересчитывает среднюю цену; в журнале одна запись «Приход на склад списком». До 100 строк за раз. Разбор вставки — `lib/receive-list.ts`, сервис — `stockInMany` в `services/inventory.ts`.

## Калькуляция (полная себестоимость)

Раздел «Меню → Калькуляция» (`/admin/costing`) считает полную себестоимость каждой позиции: **ингредиенты + упаковка + потери + амортизация оборудования + зарплата + аренда и коммунальные**, и показывает прибыль и маржу. Смотреть могут те, у кого есть `finance.view` (владелец, администратор, бухгалтер), менять оборудование — `finance.edit` (владелец, бухгалтер).

- **Ингредиенты**: количество в рецепте × средняя закупочная цена. Без рецепта себестоимость не показывается (она была бы неполной).
- **Упаковка** (стаканчик, крышка, трубочка): ингредиенты рецепта из категории «Packaging» или «Упаковка» плюс общая сумма на напиток из Настроек.
- **Потери**: процент от стоимости ингредиентов (Настройки → Калькуляция).
- **Амортизация**: «Оборудование» на странице калькуляции. Цена ÷ ресурс в напитках; оборудование можно привязать к категории (выжималка только к сокам). Выключенное оборудование не считается.
- **Зарплата**: оклад в карточке сотрудника (Сотрудники → сотрудник → «Оклад в калькуляции»), плюс процент взносов из Настроек, делится на число напитков в месяц. Кого не нужно учитывать (владелец), оставьте без оклада.
- **Аренда и прочие расходы**: из раздела «Финансы» берутся все расходы, кроме зарплаты (аренда, коммунальные, маркетинг, доставка, прочее), среднее в месяц за 90 дней; или одной суммой в Настройках. Если окладов в карточках нет, зарплатой считается расход «Зарплата» из «Финансов». Таблица «Расходы в месяц» на странице показывает все статьи и их долю на один напиток.
- **Число напитков в месяц**, на которое делятся зарплата и аренда: плановое из Настроек, а если оно 0 — фактически проданное за 30 дней. Пока продаж мало, укажите план, иначе на первые напитки ляжет вся аренда.

Расчёт чистый и покрыт тестами (`lib/costing.ts`, `tests/costing.test.ts`). Реальная себестоимость заказов в «Финансах» по-прежнему считается по ингредиентам при выдаче (`Order.cogs`); калькуляция — плановая полная себестоимость для цен и решений.
